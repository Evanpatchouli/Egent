# Electron 与设备直连改造

状态：用户已批准 SQLite 改造，并授权删除不再使用的 PostgreSQL 工程文件。功能、17 项/组测试及打包桌面验收已完成，记录归档；最终产物见 release，验收见 docs/desktop-validation.md。

## 用户明确要求

- 从共享中心服务改为每台设备运行 Electron，启动桌面端时自动启动该设备的前后端。
- 后端读取设备标识，用户输入只作昵称；身份与 IP、昵称分离。
- 发起聊天先主动连接；弹窗左侧输入新目标 IP，右侧选择历史会话人。
- 历史联系人选择后探测连通性；失败提示离线或 IP 已变，连接按钮禁用。
- 连接成功根据对方设备标识恢复历史与获取对方开放项目。
- 本会话仍不使用 DSH/子智能体，不修改无关文件。

## 已发现的架构变化

- 原先 PostgreSQL 是单服务 source of truth；每端独立运行需要明确每端数据库部署及消息同步/权威来源。
- 原先同 LAN=Owner 与姓名编码 identifier 不再适用。建议本机用户是本机项目 Owner，远程设备仅是该实例的 Colleague；双方都可在自己的实例上充当 Owner。
- 对方项目的 AgentTask 必须在对方设备执行；本地不可拿远程 projectPath 直接 spawn。复杂任务由项目所在设备的 Owner 确认。
- 设备 ID 只用于识别，不能独自作为远端认证。需设备密钥签名挑战和历史公钥校验；相同 IP 返回不同设备 ID 不可自动关联旧历史。
- 设备码建议读取 Windows MachineGuid 后做应用域 hash，不暴露原始硬件/系统标识；重装系统/克隆系统与密钥丢失有身份恢复边界，文档明确，不宣称绝对永久唯一。

## 已批准实施方向

- 首先支持 Windows 桌面；Electron main 管理后端进程及退出，React 生产静态前端由本机 HTTP 服务提供，不把 Vite dev server 打进发行包。
- renderer 隔离 Node、contextIsolation 开启，preload 只暴露最小启动/本机连接接口。
- 本机管理 API 仅本机令牌可访问；LAN 对外只提供独立的 peer 握手/聊天/项目接口，不能沿用可伪造 Owner 的 identifier API。
- 历史联系人按 deviceId + 公钥保存，IP 只是最后地址；新 IP 识别到同一设备后更新地址。探测有超时并验证协议与设备 ID，连接时再次握手，不能把 TCP 通当作应用连接成功。
- 会话由项目所在设备维护权威数据；双方持久化自己的消息副本和同步游标，重连按 ID 去重补齐；断线浏览本地历史，禁止在未验证目标设备上发送/执行。
- 双栏连接 Dialog、昵称初始化、连接状态、断线提示、重连与旧联系人更新；保持 P3/P4 消息和确认语义。
- 暂不自动合并旧姓名身份到设备身份，不删除已有 PostgreSQL 数据；升级/迁移规则需与存储决定一起明确。
- 验收包括打包启动/退出、两端隔离数据库、设备识别稳定、同昵称不同设备、改 IP 重连、错误设备拒绝、双向消息去重及远程 Owner/Agent 权限。

## 当前结果

- SQLite + Prisma/libSQL，旧 PostgreSQL 依赖/schema/迁移/专用测试已删除，未卸载服务或删数据库数据。
- Ed25519 握手、X25519 协商与 AES-GCM RPC；公钥/设备 ID 绑定历史，IP 变化可更新；本机令牌与远端权限分离。
- 前端本地 Socket，跨设备约 1.5 秒增量同步；独立 RemoteSnapshot 不触发本机 Agent。
- 17 项/组 SQLite/直连/聊天/Agent/执行器测试通过；打包后的 Electron 实际启动、昵称、连接、历史联系人、离线禁用与退出后停止后端通过。
- 已生成 Windows x64 便携版；正在同步最终改动和验收文档。
